# Plan: Contextual Help Button Module

## Overview

Create a reusable Shiny module (`mod_help_button`) that renders a small info-circle icon button. When clicked, it reads a `.md` file from the package and displays its content in a modal dialog. This is implemented as a proper Golem module so it can be dropped in anywhere in the UI with minimal boilerplate.

---

## File Structure Changes

```
R/
└── mod_help_button.R         # New: the help button module

inst/
└── app/
    └── help/                 # New directory for markdown help files
        ├── data_upload.md    # Example help file
        ├── map_selection.md  # Example help file
        └── ...               # One .md file per help topic
```

## Step 1 — Create the help content directory

Create `inst/app/help/` to hold the markdown help files. This location is accessible at runtime via the existing `app_sys()` helper:

```r
app_sys("app", "help", "data_upload.md")
```

Add an example file (`inst/app/help/data_upload.md`) as a template, e.g.:

```markdown
## Uploading Your Data

You can upload a CSV or Excel file containing ...
```

---

## Step 2 — Create `R/mod_help_button.R`

This module has two functions, following standard Golem conventions.

### UI function

Renders a minimal icon-only button using a Bootstrap link style so it sits inline with other elements without visual weight:

```r
mod_help_button_ui <- function(id) {
  ns <- NS(id)
  actionButton(
    ns("help"),
    label = NULL,
    icon = bsicons::bs_icon("info-circle"),
    class = "btn-link p-0 border-0 align-baseline",
    "aria-label" = "Help"
  )
}
```

### Server function

Reads the specified `.md` file and renders it inside a `modalDialog`. The `help_file` argument is just the filename stem (no path, no `.md` extension), keeping call sites clean:

```r
mod_help_button_server <- function(id, help_file) {
  moduleServer(id, function(input, output, session) {
    observeEvent(input$help, {
      help_path <- app_sys("app", "help", paste0(help_file, ".md"))
      showModal(
        modalDialog(
          title = NULL,
          shiny::includeMarkdown(help_path),
          easyClose = TRUE,
          footer = modalButton("Close"),
          size = "m"
        )
      )
    })
  })
}
```

`shiny::includeMarkdown()` handles the Markdown → HTML conversion using the `markdown` package (already a transitive dependency of Shiny).

## Step 4 — Usage pattern

### In any UI file

Place the button inline next to any label or control:

```r
# Example: next to a file upload input
bslib::card_body(
  tags$div(
    class = "d-flex align-items-center gap-2",
    tags$span("Upload Data"),
    mod_help_button_ui("help_upload")
  ),
  fileInput("upload", label = NULL)
)
```

### In `app_server.R` (or a parent module's server)

```r
mod_help_button_server("help_upload", help_file = "data_upload")
```

Each help button requires exactly one UI call and one server call, identified by a shared namespace ID (e.g. `"help_upload"`). The `help_file` string maps directly to a filename in `inst/app/help/`.

---

## Design decisions

| Decision | Choice | Reason |
|---|---|---|
| Module vs. plain function | Module | Golem-idiomatic; self-contained namespace avoids ID collisions |
| Icon | `bsicons::bs_icon("info-circle")` | Already imported via `bsicons`; consistent with existing UI |
| Markdown rendering | `shiny::includeMarkdown()` | Simplest approach; no extra package beyond `markdown` which is a Shiny transitive dep |
| File location | `inst/app/help/` | Accessed via `app_sys()`, so paths work in both dev and deployed contexts |
| Button style | `btn-link` | Visually lightweight; sits unobtrusively next to any UI element |

---

## Out of scope (possible future additions)

- A `title` argument to the server function to set a modal header
- A `size` reactive argument for large/small modals
- Tooltip on hover (via `bslib::tooltip()`) showing a short hint before the user clicks
